# Sackmann snapshot — SYNTHETIC test fixtures (hermetic offline corpus)

> **This directory holds SYNTHETIC fixtures, not the real Sackmann corpus.**
> The real, full 2024–2026 Jeff Sackmann corpus lives in the sibling
> [`../sackmann_corpus/`](../sackmann_corpus/README.md) directory and is
> vendored by `scripts/vendor_sackmann_corpus.py`. These two directories are
> kept deliberately separate so re-vendoring the real corpus never clobbers
> the test fixtures here (and vice-versa).

Per docs/PRD.md §7 / §12, the canonical tennis match + ranking dataset is
[`JeffSackmann/tennis_atp`](https://github.com/JeffSackmann/tennis_atp) and
[`JeffSackmann/tennis_wta`](https://github.com/JeffSackmann/tennis_wta)
on GitHub (MIT licensed, free, 1968-present).

This directory is the **synthetic, deterministic test fixture** used by the
hermetic ETL test-suite (`tests/data/test_tennis_etl.py`) and is the
`DEFAULT_SNAPSHOT_DIR` for `data.sources.tennis_sackmann.SackmannLoader`. The
runtime order is:

1. **Snapshot** (these files) — read directly, no network.
2. **GitHub raw** — only on snapshot miss (e.g. a year file not vendored
   here). Wrapped by `data.sources._http.HttpClient` so the same 3-retry
   exponential schedule applies as the other feeds.

The rows here are **synthetic but follow Sackmann's canonical header
verbatim**. They are NOT real matches: player IDs are in the contiguous
`200000+` synthetic namespace (so they never collide with real Sackmann IDs),
and the fixtures deliberately plant edge cases the ETL tests assert on:

- a row with a **blank `winner_id`** (so the missing-player_id drop is
  exercised — see `test_snapshot_has_at_least_one_missing_id_row`), and
- exactly **three ranking dates** `20240101 / 20240701 / 20250101` (so the
  asof-date ranking filter test has a known shape).

Tests also inject GitHub-503 to assert the snapshot path keeps the loader
working when upstream is dead (PRD §12 *"Sackmann CSV upstream 失效"* risk).

## Schema

Match files follow Jeff Sackmann's canonical column layout — see his repo
README for the column-by-column definitions. Key columns this project
relies on:

- `tourney_id`, `tourney_name`, `surface`, `tourney_level`, `tourney_date`
- `winner_id`, `loser_id` (player_id is the join key against rankings)
- `score`, `best_of`, `round`, `minutes`

Ranking files: `ranking_date, rank, player, points`.

## Provenance / refresh policy

These fixtures are generated by
[`data/sources/_internal/build_sackmann_snapshot.py`](../_internal/build_sackmann_snapshot.py),
which is the **source of truth for HOW they were derived** — a reviewer can
re-run it to regenerate the CSVs bit-for-bit. The literal CSVs stay committed
so tests work without running the generator.

To **bump the fixtures**, edit + re-run the synthetic generator (NOT the
vendor script — that targets `../sackmann_corpus/`). To refresh the **real**
data the flag-on real-signal path consumes, run
`python scripts/vendor_sackmann_corpus.py` (writes to `../sackmann_corpus/`).
