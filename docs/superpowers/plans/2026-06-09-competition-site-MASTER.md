- **A1 — Entry-time-ordered cached tick source + controllable clock (codex R2-HIGH chronology fix).** The loop uses the SAME `now` for settlement polling AND the next decision (`sandbox_phase2_loop.py:1431,:1448,:1484`), so the schedule must be by **ENTRY (decision) time = `entry_asof_ts_iso`**, NOT settlement time. A `_SignalSource`/`tick_inputs`-compatible source serves the cached signals per market (no Sackmann recompute) in entry-time order; the runner advances the clock to each market's entry time to DECIDE, and the poller settles any due open bets (whose `expected_settle_ts` = `end_date_iso + settle_lag`, `polymarket_sandbox_executor.py:294-307`, `sandbox_settlement_poller.py:436-441`) AT each decision tick as the clock moves forward — bets entered earlier settle "in flight" while later markets are decided, which is the faithful continuous-time model (and is when learning fires). Advancing the clock straight to `resolution_ts`/`expected_settle_ts` would make the current decision happen AFTER the market resolved (lookahead) — do NOT. **Settle-only seam (codex R9):** `_tick()` has NO clean settle-only path — it always runs the poller THEN proceeds into decision/L2/L3 (`sandbox_phase2_loop.py:1447,:1483,:1536,:1590`), and calling `loop.poller.tick()` directly is NOT equivalent (the loop also mutates open bets/bankroll + refreshes breath after the poll, `:1453,:1480`). So model settle-only advancement as **"no-market ticks": the tick source returns `None` (→ NO_BET via `no_eligible_market`, no real decision) while the clock has advanced past due `expected_settle_ts`/`resolution_ts`**, and the survival RECORDER FILTERS these synthetic NO_BETs from the journey. Confirm a no-market tick doesn't spuriously fire L2/L3 off-cadence (or accept their normal cadence). Do NOT change `SandboxExecutor` globally.
- **A2 — Multi-life FRESH-loop respawn (codex H2 fix).** A life = one `SandboxPhase2Loop.run()` (with `enable_settlement_learning=True`) until `breath<=0` death (`sandbox_phase2_loop.py:1262-1265`,`_die` `:1704-1723`). The SAME loop can NOT resurrect (`run()` returns on `_alive=False` `:1210-1222`; terminal snapshot has breath 0). So on death: capture `loop.weights` (`:1037`) + death facts, **construct a NEW loop with a NEW state dir + fresh chain adapter/breath/bankroll and `initial_weights=previous.weights`**, advance the schedule cursor past consumed markets, and define the open-bet-at-death policy (void unsettled). **Every constructed loop MUST explicitly pass `strategy_advisor=NoOpStrategyAdvisor()` by default (codex R5)** — direct loop construction otherwise DEFAULTS to the real `StrategyAdvisorImpl(GeminiClient())` (`sandbox_phase2_loop.py:941`) and would fire live Gemini in the backtest; replay avoids this the same way (`replay_runner.py:1038`). The real advisor is used ONLY when L6 is enabled (Phase B flag). **AND every constructed loop MUST pass `decision_engine=DecisionEngine(max_breath_risk_pct=seed.max_breath_risk_pct, min_bet_size_usd=seed.min_bet_size_usd, min_confidence=seed.min_confidence)` from the seed's FULL `StrategyConfig` (codex R8)** — `StrategyConfig` carries weights AND sizing/abstention knobs (`find_optimal_config.py:51`) and cached_sweep/replay thread them into `DecisionEngine` (`cached_sweep.py:265`, `replay_runner.py:1040`); a loop given only `initial_weights` falls back to `DecisionEngine()` DEFAULTS (`sandbox_phase2_loop.py:820`, `decision.py:154`), changing bet/no-bet behavior and invalidating BOTH the fragile-seed run and the static-optimum baseline. Sizing stays FIXED per seed; learning evolves the fusion `Weights` only. Repeat until markets exhausted or `max_lives` cap. **Cross-death learning persistence (codex H3 + R2-MED): share ONE INNER `WeightUpdater` instance across ALL lives** (its EMA at `weight_updater.py:287,:472` is the state that must carry), but build a **FRESH per-life `_SettlementLearningWeightUpdater(inner=shared_inner, weights_holder=new_loop)`** — the adapter is loop-bound via `weights_holder` (`settlement_learner.py:59,:101`; prod binds it to the loop at `main.py:2086`), so reusing the SAME adapter would mutate the DEAD previous loop, while a fresh INNER updater per life would drop the EMA. Carry `initial_weights=previous.weights` into the new loop AND keep feeding the shared inner updater.
- **A3 — Survival recorder + journey schema (codex H3 fix).** The loop today emits only aggregate `RunSummary`/`TickResult` (`:553-570`,`:530-550`) — no per-settlement metadata, signal snapshot, or post-settlement weights. Add an explicit **survival recorder** (a `state_hook` + a thin wrapper around the settlement-learning call in `_SettlementLearningWeightUpdater.update`) that captures per settled bet: market metadata, side/size, PnL, the decision-time signal scores, pre/post weights, running win-rate, cumulative PnL, life id, and death facts. ## Risks + rollback
- **L5 loop-driving (highest, codex H1/H2):** a DEDICATED runner constructing the loop directly + an **ENTRY-TIME-ordered** cached tick source (decisions scheduled at `entry_asof_ts_iso`, with explicit settle-only checkpoints for due open bets as the clock advances — NOT settlement-ordered, which would reintroduce lookahead) + FRESH-loop-per-life respawn is the hardest piece. Mitigation: build A0 (`SurvivalRow`) + A1 (tick source/clock) isolated, then prove ONE death→fresh-respawn→persisted-weights(+EMA) on a small fixture before the full season. Fallback if the loop is too rigid to drive in custom order: a lighter life-sim reusing the loop's BREATH constants + `breath<=0` death rule + the real `update_from_settlement` (documented fallback).
- **Settlement timing (codex H1 + R5):** settlements are due from the open-bet `expected_settle_ts` (executor: `end_date_iso + settle_lag`), not `resolution_ts_iso`. The poller selects bets where `expected_settle_ts < now` STRICTLY (`sandbox_settlement_poller.py:436,:474`), so a clock that lands EXACTLY on `expected_settle_ts` SKIPS that bet — settle-only checkpoints must advance strictly PAST it. The replay settlement client ALSO returns PENDING until the cached `resolution_ts_iso <= now` (`replay_runner.py:471`, `historical_fetcher.py:605`), so the **final-drain checkpoint after the last market must advance strictly past `max(expected_settle_ts, resolution_ts_iso)` across ALL open bets** (codex R6) — else bets stay unsettled, suppressing PnL, learner updates, and deaths. Do NOT change `SandboxExecutor` globally.
- **Recorder, not derivation (codex H3):** the journey must come from an explicit survival recorder around tick/settlement, NOT from `decisions.jsonl` (omits signal scores + settlement). EMA carries via ONE shared `WeightUpdater`.
- **Frontend reuse (codex M5/M6):** Page-2 charts need a `SurvivalJourneyFixture` adapter (not a Phase-1 cast); Page-3 needs the WS contract version-bumped + the missing emitters added.
- **Offline fonts/assets:** `@import`/`@font-face` fallback so the demo never shows a broken font.
- **Journey size:** 4925 markets → down-sample the chart series, keep full for drill-down.
- Rollback: every backend piece is flag-gated (revert = flag OFF); frontend is additive routes (revert = remove the route).
